# E-FoodHub — Marketplace Kolej Vokasional

A web-based marketplace connecting students, staff, customers and sellers across participating Kolej Vokasional campuses in Malaysia. Customers can register publicly, browse shops from different campuses and order from several stalls in one cart. Sellers identify their operating campus and require administrator approval before selling.

> **Academic project** — Diploma in Information Technology. It is not an official Ministry of Education or Kolej Vokasional platform, and campus participation requires permission from the relevant institution. Online payment is a **simulation**: no money moves and no card or bank details are collected.

## Operating model

- Public customer registration is open; every new account receives the `customer` role only.
- Any registered customer may submit a seller application. An administrator must approve the shop before it can list products.
- Every shop records its `campus_name`; the marketplace can display sellers from multiple vocational colleges together.
- Administrator privileges are never available through public registration.

## Features

**Customers (Pelanggan)** — register and sign in; search, filter (category, price, in stock), sort and paginate the catalogue; product pages with gallery, stock and reviews; a database-backed cart that can hold items from several shops; checkout with cash on collection or simulated online payment; order history with a status tracker per shop; cancel while pending; reviews after completed orders; wishlist; product reports; in-app notifications; profile and password change; apply to open a shop.

**Sellers (Penjual)** — dashboard with real figures (pending orders, completed sales for 30 days, low stock, 14-day sales chart); product create/edit with up to 5 images, stock and availability, archive/restore; order workflow (confirm → preparing → ready → completed, or reject with reason); reports for 7/30/90 days with best sellers and CSV export; shop profile.

**Administrators (Pentadbir)** — dashboard; user search/filter, suspend/reactivate, promote/demote administrators (password re-confirmation, last-admin and self-lockout protection), temporary password reset; seller application approval/rejection/suspension; product moderation queue; categories; all orders with audited status override and resolution notes; review moderation; product reports; homepage announcements; system settings; audit log.

## Technology

PHP 8.2+ (tested on 8.3), MySQL 8 / MariaDB 10.4+, HTML, CSS, vanilla JavaScript. No framework and no Composer packages: the project runs on a stock XAMPP install.

| Layer | Choice |
|---|---|
| Routing | Front controller `public/index.php` + `routes/web.php` |
| Database | PDO with prepared statements (`app/Core/Database.php`) |
| Views | Plain PHP templates in `resources/views` |
| Styling | One stylesheet with design tokens (`public/assets/css/app.css`) |
| Icons | Original inline SVG icons (`icon()` helper) — no CDN needed |
| Charts | CSS bar charts rendered on the server — no chart library needed |
| Font | Plus Jakarta Sans from Google Fonts; falls back to system fonts offline |

## Quick start (XAMPP on Windows)

1. Copy the `kvpm-e-foodhub` folder into `C:\xampp\htdocs\`.
2. Start **Apache** and **MySQL** in the XAMPP Control Panel.
3. Open <http://localhost/phpmyadmin> → **Import** → `database/schema.sql` → **Import**. Then import `database/seed.sql` for demo data.
4. Copy `.env.example` to `.env` (the defaults match XAMPP: user `root`, empty password).
5. Open <http://localhost/kvpm-e-foodhub/public/>.

Demo accounts (password `Demo@1234`, development only): `pelanggan@demo.test`, `kantin@demo.test`, `admin@demo.test`. Full list in [docs/INSTALLATION.md](docs/INSTALLATION.md).

To create a real administrator without demo data: import only `schema.sql`, then run `C:\xampp\php\php.exe database\create_admin.php`.

## Tests

```
php tests/run_tests.php
```

Builds a fresh test database from the same `schema.sql`/`seed.sql`, starts the app with PHP's built-in server and runs 58 end-to-end tests over HTTP (authentication, catalogue, cart, checkout and stock, order workflow, payments, access control, uploads, admin actions, reviews, integrity). The last recorded run is in [tests/results/latest.md](tests/results/latest.md).

The automated suite uses **SQLite** so it can run anywhere. It does not replace a final check on MySQL — see the manual checklist in [docs/TESTING.md](docs/TESTING.md).

## Known limitations

- Online payment is simulated; refunds of paid-then-cancelled orders are flagged but must be settled manually.
- No e-mail or WhatsApp sending; password recovery is done by an administrator issuing a temporary password.
- Collection at the stall only — no delivery addresses.
- No product variants (size/flavour); sellers note options in the description, customers in the order note.
- Interface is in Bahasa Melayu only.
- Automated tests ran on SQLite; MySQL-specific behaviour (row locks under real concurrency) has not been load-tested.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#roadmap) for the roadmap.

## Updating an existing database

If you already have an E-FoodHub database, back it up first, then apply `database/migrations/2026_11_03_add_campus_name_to_seller_profiles.sql` once. New installations get this field directly from `database/schema.sql`. Existing shops default to Kolej Vokasional Pasir Mas and can update their campus name from the seller dashboard under Profil Kedai.

## Deploying online

For a real hosted deployment, use the included Docker setup with a PHP-compatible host and a MySQL database. See [docs/DEPLOYMENT_RAILWAY.md](docs/DEPLOYMENT_RAILWAY.md) for the GitHub + Railway walkthrough. Netlify and GitHub Pages cannot run this PHP/MySQL backend.

For a local Docker test, run `docker compose up --build` and open <http://localhost:8080>. The compose setup initializes a fresh MySQL database from `database/schema.sql`; it does not load demo accounts. Create an administrator with `docker compose exec app php database/create_admin.php` (interactive terminal required).
